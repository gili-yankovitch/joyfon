Build

From clone to gamepad.

The order matters — flash the Pico before it disappears inside the shell.

  1. 01

    Build the firmware

    Needs CMake 3.13+, the arm-none-eabi GCC toolchain, and the pico-sdk with its TinyUSB submodule initialised. CMakeLists.txt looks for the SDK at ../pico-sdk.

    mkdir build && cd build
cmake ..            # or -DPICO_SDK_PATH=/path/to/pico-sdk
make -j

    Targeting a Pico 2 / RP2350? Configure with cmake -DPICO_BOARD=pico2 ... Either way you get build/joyfon.uf2.

  2. 02

    Flash it

    Hold BOOTSEL while plugging the Pico in. It mounts as a drive called RPI-RP2. Copy joyfon.uf2 onto it; the board reboots and comes back as Joyfon Game Controller.

  3. 03

    Print and wire the shell

    Print the twelve STLs in stl/, then wire each switch between its GPIO and GND per the pinout. The status LED on GPIO8 is active-high through a current-limiting resistor.

  4. 04

    Plug it into a phone

    Over USB-OTG or straight into USB-C, it shows up as a connected gamepad — ready for emulators or anything that speaks HID.

Before you ship any Joyfon uses the TinyUSB test IDs 0xCAFE / 0x4007. Swap in a VID/PID you own before distributing hardware. The RP2040-E5 enumeration erratum fix is enabled in CMakeLists.txt, which reserves GPIO15 on RP2040 boards.
